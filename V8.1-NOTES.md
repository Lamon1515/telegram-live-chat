# v8.1 — Notes (2026-11-08, early morning)

Fixes three reported bugs. No new features beyond these fixes; no new npm
dependencies; no AI; no canned replies. All v7/v8 behaviour kept for slash
commands.

## Bug 1 (CRITICAL): tapping an inline button clicked the WRONG button

- **Symptom:** tapping "🔙 Back" (row 8) selected "🦋 Crypto Bot" (row 0).
- **Root cause (confirmed in GramJS source):** `server.js` called
  `await targetMsg.click(row, col)` with two positional args. GramJS
  `Message.click()` takes a SINGLE OBJECT —
  `node_modules/telegram/tl/custom/message.js:518`:
  `async click({ i, j, text, filter, data, ... })`.
  Destructuring a number gives `i === undefined` and `j === undefined`,
  and its internal `findButton()` then defaults `i = 0` and returns
  `self._buttonsFlat[0]` — the FIRST button — no matter which button was
  tapped. Verified with a mock of findButton: old `click(2, 0)` returned
  "🦋 Crypto Bot"; new `click({i:2, j:0})` returns "🔙 Back".
- **Fix:** `server.js` now calls `await targetMsg.click({ i: row, j: col })`.
  Verified with grep: it is the only `.click(` call in server.js.

## Bug 2: custom commands must also support plain text (not only '/...')

- **Rule:** a custom command is `{label, command}`. `label`: required,
  trimmed, <= 30 chars. `command`: the EXACT text to send, trimmed,
  non-empty. If it starts with '/', it is a slash command
  (`/^\/[A-Za-z0-9_]{1,31}$/`, <= 32 chars). Otherwise it is plain text
  (any non-empty text, <= 64 chars) — e.g. "ব্যালেন্স" sends exactly that
  text. Dedupe by lowercased command. Max 20.
- **server.js:** `cleanCustomCommands()` updated to the rule above.
  `GET /api/bots/:username/commands` now returns each entry with a `text`
  field (the exact text to send: '/name' for slash, as-is for plain).
  Dedupe keys are '/name' for slash entries and the full text for plain
  entries (they send different text, so they never collide). A plain-text
  custom is NOT filtered by the slash-only blocked check (separate
  `isBlockedSlash` / `isBlockedPlain` helpers). Real GramJS commands also
  carry `text: '/' + name`. The /start fallback now carries `text: '/start'`.
- **Admin panel (`mla-bots-admin.php`):** `parseCustom()` now also accepts
  a line with NO '|' — the whole line becomes both label and command
  (plain text). Placeholder/help text updated to explain plain text.
  `formatCustom()` writes `label|command`, or just the text when
  label === command (round-trips through the no-'|' path). PHP
  `mla_bots_clean_one()` updated to the same rule.
- **Page (`public/bot-page-snippet.html`):** `renderCommandChips()` uses
  `var sendText = c.text || ('/' + c.command)` and sends `sendText` on
  click. Display: slash → '/' + command + (description ? ' — ' + desc);
  plain text → description || sendText. The /start fallback still works
  (`c.text` is undefined → '/start').
- **Widget (`public/widget.js`):** no command-chip rendering exists there
  (only inline-button chips for bot replies + blocked-error handling), so
  no change was needed. `node --check` still run — OK.

## Bug 3: blocked commands must also block plain-text messages

- **Rule:** `isCommandBlocked()` — if the trimmed text starts with '/',
 take
  the first word (lowercased) and check it against blocked slash entries
  (as before, so '/withdraw 100' blocks on '/withdraw'). Otherwise, check
  whether the WHOLE trimmed text (lowercased) exactly equals a blocked
  plain-text entry. Applies to both `POST /api/send` and the WS send path.
- **server.js:** `cleanBlockedCommands()` accepts plain-text entries
  (non-empty, <= 64 chars); slash entries keep the old regex (<= 32 chars).
  Dedupe, max 20.
- **Admin panel:** `parseBlocked()` now splits on commas AND newlines and
  accepts plain text. Placeholder/help text updated. PHP cleaner updated
  to the same rule.
