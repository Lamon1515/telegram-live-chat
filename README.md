# Telegram Live Chat — Node.js + Express + WebSocket (In-Memory, No Database)

ভিজিটর সাইটের চ্যাট বক্সে মেসেজ লেখে → সার্ভার Telegram bot দিয়ে তোমার Telegram-এ পাঠায় → তুমি Telegram-এ reply দিলে Webhook হয়ে সার্ভারে আসে → WebSocket দিয়ে শুধু ওই ভিজিটরের চ্যাট বক্সে real-time-এ পৌঁছায়। History ভিজিটরের ব্রাউজারের `localStorage`-এ থাকে — refresh, tab close, server restart-এও মুছে না।

## Project Structure


## কীভাবে কাজ করে

1. ভিজিটর সাইট খুললে `localStorage`-এ একটা Unique Session ID (`v_...`) তৈরি হয়; পুরোনো history-ও `localStorage` থেকে লোড হয়।
2. ভিজিটর মেসেজ পাঠায় (REST `/api/send` primary, WebSocket `/ws` শুধু reply পাওয়ার জন্য) → সার্ভার `sendMessage` দিয়ে তোমার Telegram-এ পাঠায় — মেসেজে শুধু আসল লেখাটাই থাকে, কোনো `[session-id]` ট্যাগ থাকে না (ইউনিক আইডি গোপন থাকে)। সার্ভার Telegram-এর `message_id` মনে রাখে, তাই তুমি ওই মেসেজে Reply দিলেই সঠিক ভিজিটরের কাছে উত্তর যায়।
3. তুমি Telegram-এ ওই মেসেজে Reply দিলে (বা `/reply <session> <text>` লিখলে) Telegram Webhook (`/webhook`) হয়ে সার্ভারে আসে।
4. সার্ভার `sessions` Map থেকে ওই session-এর WebSocket খুঁজে শুধু তাকেই reply পাঠায় — অন্য ভিজিটররা কিছু দেখে না।

## Safety (কোডে যা হ্যান্ডেল করা আছে)

- **Deduplication:** প্রতিটা Telegram `update_id` `Set`-এ রেখে চেক করা হয় — Telegram একই update দুইবার পাঠালেও ভিজিটর একবারই reply পায়।
- **Rate limit:** প্রতি session-এ মিনিটে ১০টা মেসেজ, প্রতি IP-তে মিনিটে ৩০টা `/api/send` কল — spam ঠেকায়।
- **Telegram 429 backoff:** Telegram rate limit দিলে `retry_after` মেনে ৩ বার পর্যন্ত retry করে।
- **Missed-update recovery:** সার্ভার চালু হওয়ার সময় webhook delete → `getUpdates` দিয়ে মিস হওয়া reply টেনে আনে → webhook আবার বসায় (শুধু `PUBLIC_URL` সেট থাকলে)।
- **localStorage history:** মেসেজ + reply ব্রাউজারে সেভ থাকে (সর্বোচ্চ ২০০টা) — refresh/server restart-এও দেখা যায়।

## Setup — Render (Free)

1. এই ফোল্ডারটা GitHub-এ push করো।
2. Render → New → Web Service → repo সিলেক্ট করো (বা `render.yaml` Blueprint ব্যবহার করো) → Build Command: `npm install`, Start Command: `npm start`।
3. Environment-এ `BOT_TOKEN`, `OWNER_CHAT_ID`, `WEBHOOK_SECRET`, `PUBLIC_URL` (যেমন `https://your-app.onrender.com`) বসাও।
4. Deploy হলে সার্ভার নিজেই webhook বসিয়ে নেবে (startup drain-এ)। না হলে নিচের Webhook ধাপটা করো।

## Webhook সেট করা (একবারই — সার্ভার নিজে না করলে)

ব্রাউজারে এই URL খুলো (TOKEN, PUBLIC_URL, SECRET বদলে নাও):

```
https://api.telegram.org/bot<TOKEN>/setWebhook?url=<PUBLIC_URL>/webhook&secret_token=<SECRET>
```

`{"ok":true,...}` দেখলে done। তারপর bot-কে Telegram-এ `/start` পাঠাও।

## Owner হিসেবে reply করার নিয়ম

- ভিজিটরের মেসেজে **Reply** (swipe/long-press → Reply) করে উত্তর লেখো — সবচেয়ে সহজ। মেসেজে কোনো session id দেখা যায় না; সার্ভার Telegram-এর `message_id` দিয়ে সঠিক ভিজিটর খুঁজে নেয়।
- অথবা লেখো: `/reply v_abc123... তোমার উত্তর` (session id দেখতে `/list` লেখো)।
- Plain মেসেজ (Reply ছাড়া) লিখলে সবচেয়ে recent active ভিজিটরের কাছে যাবে — একাধিক active ভিজিটর থাকলে বট `/reply` দিয়ে বেছে নিতে বলবে। `/list` লিখলে active ভিজিটরদের লিস্ট দেখাবে।

## বটের আসল উত্তর (কোনো ডিফল্ট/বানানো মেসেজ নেই)

বট নিজে থেকে কোনো বানানো উত্তর দেয় না। ভিজিটর কোনো যুক্ত বটের নাম/username বা "ইনকাম" লিখলে সার্ভার শুধু ওই বটের আসল তথ্য + লিংক দেয় (নিচে দেখো)। আর কিছু না মিললে মেসেজ সরাসরি তোমার কাছে (মালিকের কাছে) যায় — তুমি উত্তর দাও।

## Connected bots — অন্য টেলিগ্রাম বট যুক্ত করা (ইনকাম বট)

তোমার বট অন্য টেলিগ্রাম বটের আসল উত্তর ভিজিটরকে real-time-এ দিতে পারে। বট যুক্ত করতে `bots.json`-এ একটা entry যোগ করো, তারপর redeploy করো:

```json
{
  "bots": [
    {
      "username": "SomeEarnBot",
      "name": "Some Earn Bot",
      "description": "টাস্ক করে আয় করার বট।",
      "how_to_earn": "বটটি খুলে /start দিন, টাস্ক করুন।"
    }
  ]
}
```

- ভিজিটর "বট", "ইনকাম", "earn" বা কোনো বটের নাম/username লিখলেই সার্ভার ওই বটের আসল তথ্য + `t.me/username` লিংক instant reply দেবে (ম্যানুয়াল reply লাগে না)।
- যুক্ত বটগুলোর লিস্ট দেখা যায়: `GET /api/bots` → `{"ok":true,"bots":[...]}` — সাইটে বটের directory বানাতে এই API ব্যবহার করা যায়।
- নতুন বট যুক্ত করতে শুধু `bots.json`-এ entry যোগ করে GitHub-এ push করলেই হবে (Render auto/manual deploy)।

### WordPress এডমিন প্যানেল থেকে বট যুক্ত করা (MLA Bots) — ইউজার পেজ নয়

কোড না ঘেঁটে, শুধু wp-admin থেকেই বট যুক্ত/মুছে ফেলা যায়:

- **কোথায়:** WordPress এডমিন প্যানেলে (wp-admin) **MLA Bots** মেনু — এটা শুধু এডমিনের জন্য; ইউজার পেজে (MLA Bot পেজে) বট যুক্ত করার কোনো অপশন নেই।
- **কীভাবে:** `mla-bots-admin.php` (এই রিপোর Code Snippets-এ পেস্ট করো, "Only run in administration area" দিয়ে Activate করো) — ফর্মে বটের username, নাম, বিবরণ, কিভাবে আয় লিখে "বট যুক্ত করুন" চাপলেই হবে। মুছতে চাইলে লিস্ট থেকে "মুছুন" চাপো।
- **কী হয়:** বটের লিস্ট WordPress-এ (`mla_connected_bots` option) সেভ হয়, আর ব্রাউজার থেকেই Render সার্ভারে পাঠানো হয় (`POST /api/admin/bots/sync`) — সার্ভার সাথে সাথে নতুন বটটা চিনে নেয়, redeploy লাগে না।
- **সার্ভার রিস্টার্ট হলে:** সার্ভার `bots-runtime.json` থেকে লিস্টটা ফিরিয়ে আনে; আর MLA Bots পেজ খুললেই নিজে থেকে আবার Sync হয়ে যায় (পেজে "সার্ভারে আবার পাঠান" বোতামও আছে)।
- **নিরাপত্তা:** Sync-এ একটা গোপন কোড (`ADMIN_BOTS_SECRET` env var) লাগে — এটা শুধু wp-admin-এর snippet-এ আর Render-এ থাকে, ইউজার পেজে কখনো থাকে না। তাই ভিজিটররা বট যুক্ত/বদলাতে পারে না।

## GramJS userbot bridge — সাইট থেকে অন্যের বট চালানো (আসল উত্তর)

Bot API দিয়ে এক বট আরেক বটকে মেসেজ পাঠাতে পারে না। তাই সার্ভার GramJS (MTProto) দিয়ে তোমার **নিজের Telegram অ্যাকাউন্ট** (userbot) হিসেবেও লগইন থাকে — ওই অ্যাকাউন্ট ইনকাম বটকে কমান্ড পাঠায়, বটের আসল উত্তর সাইটে ফিরে আসে। কোনো AI নেই, কোনো বানানো মেসেজ নেই।

- ভিজিটর কোনো যুক্ত বটের নাম/username লিখে কমান্ড দিলে (যেমন `@SomeEarnBot /start`), সার্ভার বটের নামটা সরিয়ে শুধু পরিষ্কার কমান্ড (`/start`) userbot দিয়ে ওই বটকে পাঠায়। ভিজিটরের session id কখনো মেসেজে যায় না (গোপন থাকে)।
- বটের আসল উত্তর এলে সেটা ঠিক ওই ভিজিটরের চ্যাটেই যায় (WebSocket / history polling দিয়ে)। একই বটে দুজন ভিজিটর একসাথে লিখলে উত্তর গুলিয়ে যায় না — প্রতি বটে একবারে একটাই কমান্ড যায় (per-bot FIFO queue), আর বটের reply `replyToMsgId` দিয়েও মিলিয়ে নেওয়া হয়। বট ৩০ সেকেন্ডে উত্তর না দিলে কিছুই পাঠানো হয় না (বানানো মেসেজ নেই)।
- **Bridge optional:** `TG_API_ID` / `TG_API_HASH` / `TG_SESSION` না থাকলে সার্ভার এমনিই চলে (owner live-chat আগের মতো কাজ করে); শুধু ইনকাম-বট bridge বন্ধ থাকে।

### একবারের লগইন (`login.js` — লোকালি চালাও, Render-এ নয়)

1. https://my.telegram.org/apps-এ গিয়ে একটা app বানিয়ে `api_id` আর `api_hash` নাও।
2. লোকালি চালাও:
   ```
   npm install
   TG_API_ID=123456 TG_API_HASH=abcdef... node login.js
   ```
3. ফোন নম্বর দাও → Telegram-এ আসা OTP কোড দাও → 2FA পাসওয়ার্ড থাকলে সেটা দাও।
4. একটা session string ছাপা হবে — সেটা Render-এর Environment-এ `TG_SESSION` হিসেবে বসাও। এই string কখনো শেয়ার করো না, ফাইলে সেভ করো না, GitHub-এ দিও না — এটা তোমার Telegram অ্যাকাউন্টের লগইন।
5. Render-এ আরও দুটো env var বসাও: `TG_API_ID`, `TG_API_HASH`। Deploy হলেই bridge চালু হবে।

  - **`custom_commands`** — এডমিনের যুক্ত করা কমান্ড (সর্বোচ্চ ২০টি; প্রতিটা `{label, command}`, লেবেল ≤৩০ অক্ষর, কমান্ড `/` দিয়ে শুরু, ≤৩২ অক্ষর)। এগুলো বটের আসল কমান্ডের সাথে `/start`-এর পাশে চিপ হিসেবে দেখায়।
  - **`blocked_commands`** — বন্ধ করা কমান্ড (সর্বোচ্চ ২০টি, প্রতিটা `/` দিয়ে শুরু)। ভিজিটর এগুলো পাঠাতে পারবে না — পাঠালে "এই কমান্ডটি বন্ধ আছে।" দেখাবে, আর কিছুই Telegram-এ যাবে না।
- `GET /api/bots/:username/commands` এখন **মার্জ করা লিস্ট** দেয়: বটের আসল কমান্ড (GramJS `GetBotCommands`) থেকে বন্ধগুলো বাদ দিয়ে, তারপর কাস্টম কমান্ডগুলো যোগ করে। `/start` সবসময় থাকে (বন্ধ না থাকলে)। কোনো কমান্ড না থাকলে শুধু `/start` দেয়।
- **এডমিন প্যানেলে (wp-admin → MLA Bots):** বট যুক্ত করার ফর্মে "কাস্টম কমান্ড" (প্রতি লাইনে `লেবেল|কমান্ড`) আর "বন্ধ কমান্ড" (কমা দিয়ে, যেমন `/withdraw, /admin`) ফিল্ড আছে। বটের লিস্টে প্রতিটা বটের কাস্টম/বন্ধ কমান্ড দেখায়, আর **✏️ সম্পাদনা** বোতামে ফর্মে ভরে বদলানো যায়। নতুন বট wp-admin-এ যুক্ত করলে `bots.json`-এও যোগ করে রাখতে হবে — নাহলে পরের ডেপ্লয়ে বেসলাইন থেকে মুছে যাবে।

### ২) মেসেজ সিকিউরিটি — প্রতি সেশনে গোপন কোড (session secret)

- ভিজিটরের ব্রাউজার প্রথম লোডে একটা র‍্যান্ডম ৩২-অক্ষরের গোপন কোড বানায় (`localStorage`-এ `mla_chat_secret`)। `/api/send`, `/api/history`, `/api/click` আর WebSocket — সব জায়গায় এই কোড যায়।
- সার্ভার প্রথমবার কোডটা সেশনে বেঁধে রাখে; পরে অন্য/ভুল কোড এলে **403** দেয় — session id চুরি গেলেও অন্য কেউ ওই ভিজিটরের চ্যাট পড়তে বা পাঠাতে পারবে না।
- সার্ভারের লগে এখন আর পুরো মেসেজ লেখা হয় না — শুধু বটের নাম, মেসেজের দৈর্ঘ্য আর প্রথম ১৫ অক্ষর।

### ৩) মাল্টি-অ্যাকাউন্ট Userbot Pool + Auto-Shift

- একাধিক Telegram অ্যাকাউন্ট একসাথে ব্রিজের কাজ করতে পারে। Env var:
  - `TG_SESSION` (প্রধান), `TG_SESSION_2`, `TG_SESSION_3` — অথবা একটাই `TG_SESSIONS` (JSON array, যেমন `["sess1","sess2"]`)।
  - চালু হওয়ার সময় `userbot-sessions.json` (runtime ফাইল, wp-admin থেকে sync হয়) থাকলে সেটাই env-এর বদলে ব্যবহার হয় — `bots.json` vs `bots-runtime.json`-এর মতোই।
- মেসেজ যায় **সবচেয়ে ফাঁকা (কম active send) চালু অ্যাকাউন্ট** দিয়ে। কোনো অ্যাকাউন্ট FloodWait পেলে সেটা ঠান্ডা হয় (wait সেকেন্ড, সর্বোচ্চ ৬০s) আর মেসেজটা **একবার** আরেক অ্যাকাউন্ট দিয়ে আবার চেষ্টা করা হয়। অ্যাকাউন্ট ডিসকানেক্ট হলে নিজে থেকে আবার কানেক্ট হয় (backoff: 1s, 5s, 15s, 30s, তারপর ৬০s — সর্বোচ্চ ১০ বার)।
- `GET /health` এখন পুলও জানায়: `{"ok":true,"sessions":N,"userbots":{"connected":2,"total":2}}`।
- **এডমিন প্যানেলে (wp-admin → MLA Bots) "Telegram অ্যাকাউন্ট" সেকশন:** যুক্ত অ্যাকাউন্টের লিস্ট (মাস্কড ফোন, স্ট্যাটাস, চলমান মেসেজ, মুছুন বোতাম), আর "অ্যাকাউন্ট যুক্ত করুন" — ফোন নম্বর দিয়ে **OTP পাঠান** → OTP দিয়ে **Verify**। সফল হলে সেশনটা WordPress-এ (`mla_telegram_sessions`) সেভ হয়, আর পেজ খুললেই সার্ভারে আবার Sync হয় (ডেপ্লয়ের পর পুল ফিরে আসে)। সেশন string কখনো পেজে দেখানো হয় না, লগে লেখা হয় না — শুধু wp-admin আর সার্ভারের runtime ফাইলে থাকে।
- নতুন এডমিন এন্ডপয়েন্ট (সব `ADMIN_BOTS_SECRET` দিয়ে সুরক্ষিত):
  - `POST /api/admin/tg-login-start` `{phone}` — নতুন অ্যাকাউন্টের OTP পাঠানো।
  - `POST /api/admin/tg-login-verify` `{phone, code}` — OTP যাচাই; সফল হলে অ্যাকাউন্ট পুলে যুক্ত হয় আর **সেশন string রেসপন্সে ফেরত** যায় (শুধু wp-admin-এর জন্য)।
  - `GET /api/admin/accounts` — পুলের অ্যাকাউন্ট: id, মাস্কড ফোন, স্ট্যাটাস, active sends (সেশন string নেই)।
  - `POST /api/admin/accounts/sync` `{sessions:[...]}` — wp-admin থেকে পুলের সেশন লিস্ট বদলানো (ডেপ্লয়ের পর পুনরুদ্ধার)।
  - `POST /api/admin/accounts/remove` `{id}` — একটি অ্যাকাউন্ট মুছে ফেলা।

### ৪) ভবিষ্যতের জন্য (self-healing)

- একটা বট বা একটা অ্যাকাউন্ট খারাপ হলেও সার্ভার থামে না — প্রতিটা init/send `try/catch`-এ মোড়ানো, বাকিগুলো চলতে থাকে।
- নতুন বট wp-admin-এ যুক্ত করলে `bots.json`-এও যোগ করতে হবে (server.js-এ কমেন্ট আছে) — নাহলে ডেপ্লয়ে বেসলাইন থেকে মুছে যাবে।

## v8.1 — ঠিক করা হয়েছে (2026-11-08 ভোর)

### ১) বাটন ক্লিকের বড় বাগ ঠিক (CRITICAL)

- আগে যে বাটনেই ট্যাপ করা হোক, সবসময় **প্রথম বাটনটাই** ক্লিক হতো (যেমন "🔙 Back" চাপলে "🦋 Crypto Bot" সিলেক্ট হয়ে যেত)। কারণ: `server.js` `targetMsg.click(row, col)` দুটো আলাদা আর্গুমেন্ট দিত, কিন্তু GramJS-এর `Message.click()` একটাই অবজেক্ট নেয় — `click({ i, j })`। ভুল কলে `i`/`j` দুটোই undefined হয়ে যেত, আর GramJS তখন প্রথম বাটনটা ফেরত দিত। এখন `click({ i: row, j: col })` — ঠিক বাটনটাই ক্লিক হয়।

### ২) কাস্টম কমান্ডে সাধারণ লেখাও চলবে (শুধু `/` নয়)

- কাস্টম কমান্ড এখন **সঠিক লেখাটাই পাঠায়**। `/` দিয়ে শুরু হলে স্ল্যাশ কমান্ড (যেমন `/balance`); নইলে সাধারণ লেখা (যেমন শুধু `ব্যালেন্স` লিখলে চিপে ট্যাপ করলে ঠিক "ব্যালেন্স" লেখাটাই বটে যাবে)। এডমিন প্যানেলে `লেবেল|কমান্ড` লিখুন, অথবা `|` ছাড়া শুধু লেখা লিখুন — তখন ওই লেখাটাই লেবেল আর কমান্ড দুটোই।
- `GET /api/bots/:username/commands` এখন প্রতিটা এন্ট্রিতে `text` ফিল্ড দেয় — পাঠানোর সঠিক লেখা (`/name` বা সাধারণ লেখা যেমন আছে)।

### ৩) বন্ধ কমান্ডে সাধারণ লেখাও ব্লক হবে

- বন্ধ তালিকায় স্ল্যাশ কমান্ডের পাশাপাশি সাধারণ লেখাও লেখা যায় (কমা বা নতুন লাইন দিয়ে আলাদা করে)। স্ল্যাশ মেসেজে প্রথম শব্দটা দেখা হয় (`/withdraw 100` → `/withdraw`-এ ব্লক); সাধারণ লেখায় পুরো মেসেজটা হুবহু মিললে ব্লক হয়। ব্লক হলে আগের মতোই "এই কমান্ডটি বন্ধ আছে।" দেখায়, কিছুই Telegram-এ যায় না।

## v8.2 — এডমিন প্যানেলের সেভ ১০০% নির্ভরযোগ্য (2026-11-08 সকাল)

সমস্যা ছিল: ফোন থেকে কমান্ড সেভ করলে মাঝে মাঝে কিছুই সেভ হতো না — WordPress-এও খালি থাকত, সার্ভারেও খালি থাকত। কারণগুলো: (১) পেজ অনেকক্ষণ খোলা থাকলে নিরাপত্তা কোড (nonce) মেয়াদোত্তীর্ণ হয়ে যেত আর সেভ চুপচাপ ফেল করত; (২) সেভ ফেল করলেও ফর্ম আগেই মুছে যেত, লেখা হারিয়ে যেত; (৩) সার্ভার রিস্টার্ট/ডেপ্লয় হলে সেভ করা কমান্ড সার্ভারের মেমরি থেকে মুছে যেত।

- **সেভে অটো-রিট্রাই:** nonce মেয়াদোত্তীর্ণ হলে প্যানেল নিজে থেকে নতুন nonce নিয়ে আরেকবার চেষ্টা করে — হাতে কিছু করতে হয় না। তাও না হলে বড় করে ভুল দেখায়, আর লেখা ঘরেই থাকে।
- **সেভের যাচাই:** সেভের পর প্যানেল সার্ভার থেকে বটের লিস্ট এনে মিলিয়ে দেখে — কাস্টম আর বন্ধ কমান্ড হুবহু মিললে "✅ সেভ হয়েছে — সার্ভারে যাচাই হয়েছে (কাস্টম Xটি, বন্ধ Yটি)" দেখায়। না মিললে "⚠️ ওয়ার্ডপ্রেসে সেভ হয়েছে কিন্তু সার্ভারে পাওয়া যায়নি — নিচের Sync বোতাম চাপুন" দেখায়।
- **ডাবল-ক্লিক বন্ধ:** সেভ চলার সময় বোতাম বন্ধ থাকে ("⏳ সেভ হচ্ছে...")।
- **ঘরগুলো আর ধোঁকা দেয় না:** কাস্টম/বন্ধ ঘরের ভেতরের ধূসর লেখা এখন শুধু ছোট উদাহরণ — ঘরের নিচে পরিষ্কার করে লেখা আছে ঘরটি খালি থাকে, নিজে লিখতে হবে, আর সাধারণ লেখাও চলবে।
- **সম্পাদনা পরিষ্কার:** কোনো বট বদলাতে তার পাশের ✏️ সম্পাদনা চাপতে হয় — এডিট করলে উপরে হলুদ ব্যানার দেখায়, আর বোতামের নিচে লেখা আছে নতুন করে যুক্ত করলে হবে না।
- **প্রতি ঘণ্টায় অটো-সিঙ্ক:** WordPress এখন প্রতি ঘণ্টায় নিজে থেকে বটের লিস্ট সার্ভারে পাঠায় (wp-cron) — সার্ভার রিস্টার্ট/ডেপ্লয় হলেও কমান্ড হারাবে না, এডমিন পেজ খুলতে হবে না। পেজে "শেষ সিঙ্ক: [সময়]" দেখায়।

## v8.3 — সেভের পর আর "ডেমো" মনে হবে না (2026-11-08 সকাল)

সমস্যা ছিল: সেভ চাপলে "⏳ সার্ভারে পাঠানো হচ্ছে..." লেখাটা আটকে থাকত — সফল হলেও আর বদলাত না, তাই মনে হতো কিছুই হয়নি (আসলে সিঙ্ক হয়ে যেত, "শেষ সিঙ্ক"-এর সময় বদলাত — প্রমাণ আছে)। আর ভুল ফরম্যাটের লাইন (যেমন স্পেস থাকা কমান্ড) চুপচাপ বাদ পড়ে যেত — সেভ সফল দেখাত, কিন্তু ইউজার পেজে কমান্ড আসত না।

- **Sync-এর পরিষ্কার ফল:** সার্ভারে পাঠানো হলে "✅ সার্ভারে পাঠানো হয়েছে — Xটি বট চালু আছে।" দেখায়; না হলে লাল করে "❌ সার্ভারে পাঠানো যায়নি — নেটওয়ার্ক/সার্ভার সমস্যা, আবার চেষ্টা করুন।" দেখায়। Sync বোতামেও একই ফল দেখায়।
- **১৫ সেকেন্ডের সীমা:** সার্ভার ঘুম থেকে উঠতে দেরি করলে বা নেট ধীর হলে সেভ/যাচাই আর অনন্তকাল আটকে থাকবে না — ১৫ সেকেন্ডে সময় শেষ হলে পরিষ্কার ভুল দেখায়, আবার চেষ্টা করা যায়।
- **বাদ পড়া লাইন এখন নাম ধরে বলে:** ভুল ফরম্যাটের লাইন (স্পেস আছে / ভুল ফরম্যাট / ৬৪ অক্ষরের বেশি) সেভের পরেই লাল করে দেখায় — যেমন "⚠️ এই লাইনগুলো সেভ হয়নি: '/my command' (স্পেস আছে) — / দিয়ে শুরু হলে শুধু অক্ষর/সংখ্যা/_ চলবে, স্পেস চলবে না।" ঠিক লাইনগুলো সেভ হয়, বাকিগুলো শুধু জানিয়ে দেওয়া হয়।
- **টেবিলে সাথে সাথে দেখা যায়:** সেভের পর "কাস্টম / বন্ধ কমান্ড" কলামে সেভ হওয়া কমান্ডগুলো সাথে সাথে দেখায় — খালি থাকলে "—" দেখায়, মানে কিছুই সেভ হয়নি।

## v8.4 — বন্ধ কমান্ড বাটন ট্যাপেও ব্লক হবে (2026-11-08 সকাল)

সমস্যা ছিল: বন্ধ তালিকায় \"💳 payout\" লিখে সেভ করলে **লিখে পাঠালে** ঠিকই ব্লক হতো, কিন্তু বটের নিজের \"💳 Payout\" **বাটনে ট্যাপ করলে** ব্লক হতো না — বাটন ক্লিক হয়ে বট উত্তর দিত। কারণ: টাইপ করা মেসেজ `/api/send`-এ `isCommandBlocked()` দিয়ে যাচাই হতো, কিন্তু বাটন ট্যাপ `POST /api/click`-এ সেই যাচাই ছিলই না।

- **বাটন ট্যাপেও একই ব্লক:** বাটনের লেবেল (যেমন \"💳 Payout\") বন্ধ তালিকার কোনো এন্ট্রির সাথে মিললে ক্লিক করা হয় না — সার্ভার `{ok:false, error:'blocked'}` ফেরত দেয়, Telegram-এ কিছুই যায় না। নিয়ম টাইপ করা মেসেজের মতোই: স্ল্যাশ এন্ট্রি প্রথম শব্দে মেলে, সাধারণ লেখা পুরো লেবেল হুবহু মিললে (ছোট-বড় হাতের অক্ষর ধরা হয় না)।
- **URL বাটন ব্লক হয় না:** যে বাটন লিংক খোলে (যেমন ওয়েবসাইটের লিংক), তার লেবেল বন্ধ তালিকায় থাকলেও লিংক খুলবে — লিংক খোলা মানে বটে কমান্ড পাঠানো নয়।
- **ব্লক হওয়া বাটনে সঠিক মেসেজ:** ব্লক হওয়া বাটনে ট্যাপ করলে পেজ আর উইজেট দুটোতেই \"এই কমান্ডটি বন্ধ আছে।\" দেখায় (দুটো `clickButton` হ্যান্ডলারেই `error:'blocked'`-এর আলাদা মেসেজ যোগ করা হয়েছে) — লাইভ টেস্টে যাচাই করা হয়েছে: \"💳 Payout\" ট্যাপে এই মেসেজ এসেছে, বট কোনো উত্তর দেয়নি।

## v9.0 — আসল Telegram ডিজাইন (2026-11-08 সকাল)

লেমন বলল \"টেলিগ্রাম আসল ডিজাইন বানিয়ে দাও\" — তাই MLA Bot পেজের (page 1777) শুধু দেখতে বদলে দেওয়া হয়েছে, ভেতরের কাজ একটুও বদলায়নি। সার্ভার, এডমিন প্যানেল, উইজেট — কিছুই ছোঁয়া হয়নি; শুধু পেজের snippet (`public/bot-page-snippet.html`) নতুন করে সাজানো হয়েছে।

- **হেডার (Telegram চ্যাট হেডার):** বামে ‹ চিহ্ন (চাপ দিলে বটের তালিকা লুকায়/দেখায়), তারপর গোল অবতার — বটের নামের প্রথম অক্ষর Telegram-নীল গ্রেডিয়েন্ট বৃত্তে; নাম মোটা অক্ষরে, নিচের লাইনে নীল করে \"online\" লেখা (@username • online • v9.0)।
- **বটের তালিকা (Telegram চ্যাট লিস্ট):** বট বাছাই এখন চিপ নয় — Telegram-এর চ্যাট লিস্টের মতো সারি: গোল অবতার (প্রতি বটের আলাদা রং), নাম মোটা অক্ষরে, নিচে তার বিবরণের এক লাইন, আর বাছাই করা বটের সারি হালকা নীল + ✓ চিহ্ন। এক ট্যাপে বট বদলায়, আগের মতোই।
- **চ্যাটের জায়গা:** Telegram-এর হালকা ধূসর-নীল ব্যাকগ্রাউন্ড (সূক্ষ্ম ডটের ছোঁয়া, কোনো ছবি নয়)। বটের মেসেজ সাদা বাবল (বামে, ছোট লেজ), তোমার মেসেজ হালকা Telegram-নীল বাবল #d6e9f8 (ডানে) — দুটোতেই হালকা ছায়া, গাঢ় লেখা।
- **সময় আর টিক:** প্রতি বাবলে ছোট ধূসর সময় (HH:MM) থাকে ডানদিকে নিচে; তোমার মেসেজে সময়ের পরে নীল ✓✓ থাকে।
- **বটের বাটন (inline keyboard):** এখন Telegram-এর মতো — মেসেজের নিচে লেগে থাকা পুরো চওড়া বাটন (হালকা নীল-ধূসর #e8f1f8, নীল লেখা, গোল কোণা); এক সারির বাটনগুলো পাশাপাশি সমান চওড়া। ট্যাপ করলে আগের মতোই `/api/click` যায়, ব্লক থাকলে \"এই কমান্ডটি বন্ধ আছে।\" দেখায়।
- **কমান্ড চিপ (উপরে):** Telegram-এর কমান্ড মেনুর মতো নরম ধূসর পিল (#f0f2f5, গাঢ় লেখা), পাশে স্ক্রল করা যায়; /start তার জায়গায়ই আছে।
- **লেখার জায়গা (নিচে):** Telegram-এর কম্পোজার — গোল (pill) সাদা লেখার ঘর, হালকা বর্ডার আর ছায়া; ডানে গোল Telegram-নীল পাঠানোর বোতাম (➤)। 📎 আর 🙂 আইকন ইচ্ছে করে বসানো হয়নি — ওগুলো চাপ দিলে আপলোড/ইমোজি কিছুই হতো না, আর লেমন \"কাজ করে না\" এমন কিছু চায় না; ফোনের কিবোর্ডের নিজের ইমোজি বোতামই যথেষ্ট।
- **সিস্টেম লাইন:** \"এই কমান্ডটি বন্ধ আছে।\"-এর মতো লাইনগুলো এখন Telegram-এর মতো মাঝখানে ধূসর পিল (ছোট, গোল, ধূসর লেখা)।

## v9.1 — চ্যাটের স্ক্রিপ্ট এখন প্লাগিন থেকে লোড হয় (2026-11-08 সকাল)

v9.0 ডেপ্লয় হওয়ার পর দেখা গেল ডিজাইন ঠিকই দেখাচ্ছে, কিন্তু চ্যাটের কিছুই কাজ করছে না — বটের তালিকা খালি, কমান্ড চিপ নেই, লেখা পাঠালে পেজ রিলোড হয়। কারণ: সাইটের থিম পেজের কনটেন্ট ক্লায়েন্ট-সাইডে (PJAX-এর মতো) লোড করে, আর তাতে Custom HTML ব্লকের ভেতরের `<script>` আর চলেই না (CSS চলে, JS চলে না)।

- **ভাগ হয়ে গেছে:** পেজের snippet (`public/bot-page-snippet.html`, v9.1) এখন শুধু HTML + CSS — কোনো `<script>` নেই, দেখতে একটুও বদলায়নি। চ্যাটের JavaScript আলাদা ফাইলে গেছে: `mla-bots-admin/bot-page-script.js` (v9.0-র স্ক্রিপ্ট হুবহু, শুধু ভেতরের দুটো \"v9.0\" লেখা \"v9.1\" হয়েছে)।
- **প্লাগিন থেকে লোড:** MLA Bots এডমিন প্লাগিন (v1.1.4) এখন MLA Bot পেজে (page 1777) `wp_enqueue_scripts` দিয়ে এই JS ফাইলটা ফুটারে লোড করে — WordPress এটাকে আসল `<script src>` হিসেবে ছাপায়, তাই ব্রাউজার সবসময় চালায়। শুধু 1777 পেজেই লোড হয় (permalink বা `?page_id=1777`, দুইভাবেই); JS ফাইল না থাকলে কিছুই লোড হয় না (কোনো এরর নয়)। কোনো ডিপেন্ডেন্সি নেই (jQuery লাগে না), ভার্সন '9.1' দিয়ে ক্যাশ-বাস্ট হয়।
- **যা বদলায়নি:** JS-এর কাজ একটুও বদলায়নি — সব API কল, localStorage চাবি, মেসেজ, বাটন, ব্লক — সব আগের মতোই। সার্ভার ছোঁয়া হয়নি (Render ডেপ্লয় লাগে না)।
- **একটা সীমা জেনে রাখো:** মেনু দিয়ে পেজে গেলে থিম PJAX-এ কনটেন্ট বদলায় — তখন ফুটারের স্ক্রিপ্ট আবার লোড হয় না (এটা থিমের সীমা)। পেজের ঠিকানা সরাসরি খুললে (ফুল লোড) সব ঠিক চলে। মেনু নেভিগেশনেও যাতে চলে, সেটা থিমের কাজ — পরে আলাদা করে দেখতে হবে।

## v9.2 — মোবাইলে পুরো স্ক্রিন, নড়াচড়া বন্ধ, প্রিমিয়াম ডিজাইন (2026-11-08 সকাল)

লেমন খুশি হয়ে বলল মোবাইলে যেন চ্যাটটা একদম স্থির থাকে (নড়াচড়া না করে), পুরো স্ক্রিন জুড়ে দেখা যায়, আর ডিজাইন যেন প্রিমিয়াম হয়। তাই v9.2-তে পেজের দেখতে আর স্থিরতায় কাজ হয়েছে — ভেতরের কাজ (সার্ভার, API, বট, কমান্ড, ব্লক) একটুও বদলায়নি।

- **পুরো স্ক্রিন (মোবাইল):** ৬৪০px বা ছোট স্ক্রিনে চ্যাট এখন পুরো স্ক্রিন জুড়ে — `100dvh` (মোবাইল ব্রাউজারের উপরে-নিচে বার/কিবোর্ড খুললেও ফাঁক থাকে না), সাথে `100vh` ফলব্যাক পুরোনো ব্রাউজারের জন্য। পুরো চ্যাট একটা flex কলাম: হেডার উপরে, চ্যাটের তালিকা মাঝখানে বেড়ে পুরো জায়গা নেয়, লেখার জায়গা নিচে। চ্যাটের তালিকা ভেতরে ভেতরে স্ক্রল হয়, পেজ নিজে স্ক্রল হয় না — পুরো চ্যাট এক স্ক্রিনেই। ডেস্কটপে আগের মতো মাঝখানে ৫৬০px কার্ড।
- **নড়াচড়া বন্ধ (স্থির):** (১) লেখার ঘরের অক্ষর এখন ১৬px — iOS ১৬px-এর নিচে লেখার ঘরে ট্যাপ করলেই নিজে থেকে জুম করে ফেলত, সেই জুম-ঝাঁকুনিই ছিল আসল সমস্যা; ১৬px-এ আর জুম হয় না। (২) চ্যাটের তালিকা আর পেজে `overscroll-behavior: contain` — চ্যাট স্ক্রল করলে পুরো পেজ আর টেনে/বাউন্স করে না। (৩) কোথাও পাশে স্ক্রল নেই — বাবল সর্বোচ্চ ৭৫% চওড়া, লম্বা লিংক/শব্দ ভেঙে যায় (`overflow-wrap: anywhere`), কনটেইনারে `overflow-x: hidden`। (৪) লেখার জায়গা `fixed` নয় — flex কলামের নিচে স্বাভাবিকভাবে থাকে, তাই কিবোর্ড খুললেও লাফায় না। (৫) নতুন মেসেজ এলে তালিকা নিচে মসৃণভাবে গড়িয়ে যায় (smooth scroll), আর তুমি উপরে পুরোনো মেসেজ পড়তে থাকলে নতুন মেসেজ তোমাকে টেনে নিচে নামায় না। (৬) অবতার/বাটনের মাপ নির্দিষ্ট — লোড হতে হতে লেআউট সরে না।
- **প্রিমিয়াম ছোঁয়া:** হেডার এখন হালকা কাঁচের মতো (frosted, blur — না চললে সাদা ব্যাকগ্রাউন্ড), নিচে নরম ছায়া। অবতারে আরও গভীর Telegram-নীল গ্রেডিয়েন্ট (প্রতি বটের আলাদা রং) + সাদা রিং আর ছায়া। বাবলে নরম দুই স্তরের ছায়া, একটু বড় গোল কোণা (১৪px), পাঠানো বাবলের নীল একটু গাঢ় (#cde9f8), লেখা প্রায় কালো (#111)। সময় ছোট আর আরও হালকা ধূসর, টিক নীল। বাটন আর চিপে চাপ দিলে হালকা ছোট হওয়ার (press) অ্যানিমেশন; পাঠানোর বোতামে নরম নীল আভা + চাপে ০.৯২ গুণ ছোট হয়। নতুন মেসেজ এলে হালকা ভেসে ওঠে (fade + সামান্য ওপরে ওঠা, ~১৫০ms) — শুধু নতুন মেসেজে, পুরো ইতিহাস লোডের সময় নয়। সব CSS-ই — কোনো বাইরের ফন্ট/ছবি নেই, ফোন ভারী হয় না।
- **যা বদলায়নি:** সব API কল, localStorage চাবি, মেসেজ পাঠানো/পাওয়া, বাটন ক্লিক, ব্লক যাচাই, প্রতি বটের আলাদা চ্যাট — সব আগের মতোই। সার্ভার ছোঁয়া হয়নি (Render ডেপ্লয় লাগে না)। প্লাগিন v1.1.5, পেজ v9.2।
- **একটা সীমা জেনে রাখো:** মেনু দিয়ে পেজে গেলে থিম PJAX-এ কনটেন্ট বদলায় — তখন ফুটারের স্ক্রিপ্ট আবার লোড হয় না (v9.1-এর মতোই, থিমের সীমা)। পেজের ঠিকানা সরাসরি খুললে (ফুল লোড) সব ঠিক চলে। আর থিমের নিজের হেডার/ফুটার পেজের বাইরে থাকে — চ্যাট তার নিচের জায়গাটা পুরো ভরে, থিমের হেডার সরানো snippet-এর কাজ নয়।

## v9.3 — হেডার/মেনু স্থির + কালো/সাদা থিম (2026-11-08 সকাল)

লেমন ঠিক করে বলল আসল সমস্যা কী: মোবাইলে পেজে গেলে উপরের হেডার আর নিচের মেনু নড়াচড়া করে, বাজে দেখায়। আর কালো/সাদা থিম বদলালে চ্যাটের লেখা আর রং বদলায় না। তাই v9.3-তে দুটো বড় কাজ হয়েছে — ভেতরের কাজ (সার্ভার, API, বট, কমান্ড, ব্লক) একটুও বদলায়নি।

- **হেডার/মেনু লুকানো হয়নি — স্থির করা হয়েছে:** প্রথমে ভাবা হয়েছিল হেডার-মেনু লুকিয়ে ফেললে ঠিক হবে, কিন্তু লেমন বলল "হেডার মেনু লুকাবে কেন?" — ঠিক কথা। তাই দুটোই যেমন আছে তেমন দেখা যায়, শুধু আর নড়ে না। (১) চ্যাট এখন উপরের হেডার (`#mla-topbar`) আর নিচের মেনুর (`#bottomNav`) মাঝখানে ঠিক মাপে বসে — JS চালু হওয়ার সময় দুটোর আসল উচ্চতা মেপে চ্যাটের উচ্চতা ঠিক করে (`calc(100dvh - headerH - bottomNavH)`), আর ফোন ঘোরালে বা উইন্ডো বদলালে আবার মেপে ঠিক করে। (২) এই পেজে পেজ নিজে আর স্ক্রল হয় না (`body.page-id-1777` — শুধু এই পেজ), চ্যাটের তালিকা ভেতরে ভেতরে স্ক্রল হয় — তাই হেডার-মেনু আর সরে না। (৩) নিচের মেনুর `bottom` ট্রানজিশন (যেটা মেনুটাকে স্লাইড করাত) এই পেজে বন্ধ করে `bottom: 0`-তে আটকে দেওয়া হয়েছে; উপরের হেডারের ট্রানজিশনও বন্ধ। (৪) ভাসমান "Spin Now" 🎡 বোতামটা এই পেজে লুকানো হয় (JS দিয়ে খুঁজে — এর কোনো স্থির id/class নেই, তাই "Spin Now" লেখা দেখে চেনা হয়) — ওটা চ্যাটের ওপর ভেসে থাকত। ডেস্কটপে আগের মতো মাঝখানে ৫৬০px কার্ড।
- **কালো/সাদা থিম — চ্যাট এখন থিমের সাথে বদলায়:** সাইটের থিম বোতাম চাপলে `html`-এর `data-theme` বদলায় — সাদায় `data-theme="light"`, কালোতে attribute-টাই থাকে না (`data-theme="dark"` বলে কিছু নেই)। তাই চ্যাটের সব রং এখন CSS ভেরিয়েবল: সাদা `html[data-theme="light"]`-তে (আগের Telegram সাদা প্যালেট), কালো `html:not([data-theme="light"])`-তে (Telegram-এর আসল কালো প্যালেট — চ্যাটের পেছন #0e1621, হেডার/লেখার ঘর #17212b, আসা বাবল #182533, পাঠানো বাবল #2b5278, লেখা #e8eef4, হালকা লেখা #7f91a4, বাটন #2b5278-তে #64b5ef লেখা)। বাবল, চিপ, বাটন, বটের তালিকা, লেখার ঘর, সময়, সিস্টেম লাইন — সব কিছুর রং ভেরিয়েবল দিয়ে, তাই থিম বদলালে পেজ রিলোড ছাড়াই সাথে সাথে রং বদলে যায়, লেখা দুটো থিমেই পরিষ্কার পড়া যায়। Telegram-নীল অ্যাকসেন্ট (#0088cc) আর পাঠানোর বোতামের গ্রেডিয়েন্ট দুটো থিমেই একই। পেজের "MLA Bot" শিরোনাম (h1) আগের মতোই আছে — লুকানো হয়নি।
- **ব্যাক (‹) বোতাম:** আগের মতোই শুধু বটের তালিকা খোলে/লুকায় — হোমে যায় না, কারণ নিচের মেনুতে হোম আছেই।
- **যা বদলায়নি:** সব API কল, localStorage চাবি, মেসেজ পাঠানো/পাওয়া, বাটন ক্লিক, ব্লক যাচাই, প্রতি বটের আলাদা চ্যাট — সব আগের মতোই। সার্ভার ছোঁয়া হয়নি (Render ডেপ্লয় লাগে না)। প্লাগিন v1.1.6, পেজ v9.3।
- **একটা সীমা জেনে রাখো:** মেনু দিয়ে পেজে গেলে থিম PJAX-এ কনটেন্ট বদলায় — তখন ফুটারের স্ক্রিপ্ট আবার লোড হয় না (v9.1-এর মতোই, থিমের সীমা)। পেজের ঠিকানা সরাসরি খুললে (ফুল লোড) সব ঠিক চলে। আর "Spin Now" বোতামটা লেখা দেখে চেনা হয় — থিম ওটার লেখা বদলালে লুকানোটা আর কাজ নাও করতে পারে।

## v9.4 — কালো থিম + ফিটের আসল ঠিক (2026-11-08 সকাল)

v9.3 লাইভ চেক করতে গিয়ে দুটো জিনিস ধরা পড়ল: (১) কালো থিমে চ্যাট কালো হয় না, উল্টো লেখা সব অদৃশ্য হয়ে যায় (সাদা লেখা হালকা পেছনে); (২) ডেস্কটপে লেখার ঘর (composer) স্ক্রলের নিচে চলে যায় — চ্যাট হেডার-মেনুর মাঝখানে ঠিকমতো বসে না।

**আসল কারণ:** v9.3-এর সব CSS (থিমের ভেরিয়েবল, পেজের স্ক্রল বন্ধ, হেডার/মেনুর পিন) ছিল snippet-এর `<style>` ব্লকে — WordPress/Elementor পোস্টের ভেতরের `<style>` ছেঁটে ফেলে বা চালায় না, তাই একটাও নিয়ম লাইভ পেজে পৌঁছায়নি। ভেরিয়েবলগুলো undefined থাকায় সব `var(--...)` অচল হয়ে যায় (পেছন স্বচ্ছ/হালকা, লেখা সাইটের কালো থিমের সাদা রং ধরে — অদৃশ্য)। আর overflow/pin নিয়ম না থাকায় পেজ স্ক্রল হতো, লেখার ঘর নিচে চলে যেত। সাদা থিমে ঠিক দেখাত কারণ HTML-এর inline style-গুলো বেঁচে যায় — শুধু `<style>`-টাই হারায়।

**ঠিক (v9.4):**
- **সব CSS এখন প্লাগিনে:** `mla-bots-admin.php`-তে নতুন `wp_head` অ্যাকশন (priority 5, শুধু পেজ 1777-এ) পুরো CSS-টা `<style id="mla-bot-page-css">` হিসেবে `<head>`-এ বসায় — WordPress এটা ছাঁটতে পারে না। মান একটাও বদলায়নি, v9.3-এর CSS হুবহু সরানো হয়েছে (শুধু কমেন্টের লেবেল বদলেছে)। ফলে কালো থিমে চ্যাট সত্যিই কালো হয়, লেখা দুটো থিমেই পরিষ্কার পড়া যায়; আর পেজের স্ক্রল বন্ধ + হেডার/মেনুর পিন এখন সত্যিই কাজ করে।
- **ফিট এখন সব চওড়ায়:** JS-এর `fitChat()`-এর `≤640px` শর্ত তুলে দেওয়া হয়েছে — এখন ডেস্কটপেও হেডার আর মেনুর আসল উচ্চতা মেপে চ্যাট ঠিক তাদের মাঝখানে বসে, লেখার ঘর স্ক্রল ছাড়াই দেখা যায়। ডেস্কটপে আগের মতো মাঝখানে ৫৬০px কার্ড — শুধু উচ্চতাটা মাপা হয়। ফোন ঘোরালে/উইন্ডো বদলালে আবার মাপা হয়।
- **snippet এখন শুধু HTML:** `public/bot-page-snippet.html` থেকে `<style>` ব্লকটা পুরো সরানো হয়েছে — এখন শুধু HTML + inline style, কোনো `<script>` বা `<style>` নেই। inline style-গুলো `var(--...)` ব্যবহার করে, যেগুলো এখন প্লাগিনের `<style>` থেকে মেলে।
- **যা বদলায়নি:** সব API কল, localStorage চাবি, মেসেজ পাঠানো/পাওয়া, বাটন ক্লিক, ব্লক যাচাই, প্রতি বটের আলাদা চ্যাট, হেডার/মেনু দেখা যায় (লুকানো হয়নি), Spin Now লুকানো — সব আগের মতোই। সার্ভার ছোঁয়া হয়নি (Render ডেপ্লয় লাগে না)। প্লাগিন v1.1.7, পেজ v9.4।

## v9.5 — কালো থিমে চ্যাটের তালিকা + ফিটের শেষ ঠিক (2026-11-08 সকাল)

v9.4 লাইভ চেক করতে গিয়ে দুটো জিনিস ধরা পড়ল: (১) কালো থিমে বাবল/বাটন/তালিকা/লেখার ঘর কালো হয় আর লেখা পরিষ্কার — কিন্তু চ্যাটের তালিকার (মেসেজের জায়গা) পেছনটা সাদাই থেকে যায়; (২) নতুন করে পেজ খুললে লেখার ঘর (composer) স্ক্রলের নিচে থাকে — উপরে "MLA Bot" শিরোনামের জায়গা প্রায় ৩৩০px সাদা ফাঁকা রেখে চ্যাট শুরু হয়, আর তালিকা নিচের মেনুর নিচ দিয়ে চলে যায়।

**আসল কারণ:**
- (১) তালিকাটাই একমাত্র জায়গা যেখানে `background-color` এর সাথে ডটের ছাপের `background-image: radial-gradient(...)` ছিল। বাকি সব জায়গা সাদামাটা `background: var(...)` ব্যবহার করে — তাই ওগুলো কালো হয়, আর ডটের ছবিওয়ালা তালিকাটা হয় না।
- (২) `fitChat()` শুধু হেডার আর মেনুর উচ্চতা মেপে চ্যাটের উচ্চতা ঠিক করত — চ্যাটটা স্ক্রিনের উপর থেকে কতটা নিচে শুরু হয়েছে সেটা মাপত না। শিরোনামের ফাঁকায় চ্যাট ~৩৩০px নিচে শুরু হয়, তাই চ্যাট স্ক্রিনের নিচ দিয়ে ~৩৩০px বেরিয়ে যেত, লেখার ঘর কাটা পড়ত।

**ঠিক (v9.5):**
- **তালিকার পেছন এখন সমতল রং:** তালিকার inline style থেকে ডটের ছাপ (`background-image` + `background-size`) পুরো সরানো হয়েছে — এখন সাদামাটা `background: var(--mla-list-bg)` (বাবলগুলোর মতোই প্যাটার্ন)। ফলে কালো থিমে পুরো চ্যাট — তালিকার পেছনসহ — কালো হয়, সাদা থিমে সাদা। আর দরকার নেই বলে `--mla-dot` ভেরিয়েবলটাও দুটো থিমের নিয়ম থেকে সরানো হয়েছে।
- **ফিট এখন উপর থেকে মাপা:** `fitChat()` এখন চ্যাটের বাক্সটা স্ক্রিনের উপর থেকে কতটা নিচে আছে সেটা মাপে (`getBoundingClientRect().top`) আর উচ্চতা ঠিক করে `স্ক্রিনের উচ্চতা - উপরের ফাঁকা - মেনুর উচ্চতা`। হেডারের উচ্চতা আর আলাদা করে মাপার দরকার নেই (উপরের ফাঁকায় ওটা ধরাই আছে)। ফোন ঘোরালে/উইন্ডো বদলালে/লোডের পরে আবার মাপা হয়।

- **যা বদলায়নি:** সব API কল, localStorage চাবি, মেসেজ পাঠানো/পাওয়া, বাটন ক্লিক, ব্লক যাচাই, প্রতি বটের আলাদা চ্যাট, হেডার/মেনু দেখা যায় (লুকানো হয়নি), Spin Now লুকানো, ব্যাক বোতামের picker টগল — সব আগের মতোই। সার্ভার ছোঁয়া হয়নি (Render ডেপ্লয় লাগে না)। প্লাগিন v1.1.8, পেজ v9.5।

## v9.6 — কালো থিমের বাকি সাদা জায়গাগুলো JS দিয়ে সরাসরি কালো (2026-11-08 দুপুর)

v9.5 লাইভ চেক করতে গিয়ে দেখা গেল ফিট ঠিক হয়েছে (লেখার ঘর দেখা যায়, শিরোনামের ফাঁকা নেই, হেডার/মেনু দেখা যায়), সাদা থিমে সব পরিষ্কার, মেসেজ/চিপ/বাটন/ব্লক সব কাজ করে — কিন্তু **কালো থিমে মেসেজের তালিকার পেছন, চ্যাটের হেডার বার আর চিপের লাইনটা সাদাই থেকে যায়** (তালিকায় ডটের ছাপও দেখা যায়), যদিও বাবল/বটের তালিকা/লেখার ঘর কালো হয়।

**আসল কারণ:** তিন সংস্করণ ধরে এই জায়গাগুলোর রং CSS ভেরিয়েবলের (`var(--...)`) উপর নির্ভর করছিল — কিন্তু এই কয়েকটা জায়গায় ভেরিয়েবল ঠিকমতো পৌঁছায় না (পুরোনো HTML ক্যাশে থাকা, স্থির জায়গাগুলোতে ভেরিয়েবল না মেলা, বা প্লাগিনের `<style>` ওগুলো পর্যন্ত না পৌঁছানো — তিন সংস্করণ পরেও ঠিক কোনটা, তা প্রমাণ হয়নি)। তাই ভেরিয়েবলের উপর ভরসা ছেড়ে দেওয়া হয়েছে।

## সত্যি কথাগুলো (জেনে রাখো)

- **Token গোপন রাখো।** `.env` কখনো শেয়ার করো না, GitHub-এ push করো না।
