# v8.3 — Admin Panel: Save No Longer Feels Like a Demo (2026-11-08 morning)

Version: plugin **1.1.2 → 1.1.3**. Only `mla-bots-admin.php` changed.
`server.js`, `widget.js`, `bot-page-snippet.html`, `bots.json` untouched — **no Render deploy needed**.

## Why (the user's exact complaint)

> "save চাপ দিলে তার পরেও ইউজার পেইজ থেকে ব্লক কমান্ড একরে আর ডিফল্ট কমান্ড /start কমান্ড এ শো করে না... save এ চাপ দিলে বুজা যায় যেনো demo"

A read-only diagnostic proved `wp_options` had **no custom/blocked commands stored for either bot**, and the Sync button got **stuck on "⏳ সার্ভারে পাঠানো হচ্ছে..." for 2+ minutes** with no completion message. Two confirmed bugs in the admin panel JS:

**BUG 1 (confirmed):** `syncToServer()` set the status to "⏳ সার্ভারে পাঠানো হচ্ছে..." but **never called setStatus on success** — it only called `markSynced()` and returned `true`. The status stayed on "sending..." forever even when the sync worked (the last-sync timestamp updated, proving the fetch returned ok). The user saw "sending..." and concluded nothing happened.

**BUG 2 (likely):** if the sync fetch hung (Render waking from sleep, slow phone network), the save flow stalled at the "sending..." step and `verifySaved` never ran, so the user never saw the final verified message. Separately, `parseCustom`/`parseBlocked` **silently dropped** lines that didn't match the format (e.g. a slash command with a space or a hyphen) — the save then succeeded with 0 commands and the user had no idea his line was rejected.

## What changed (all in `mla-bots-admin.php`)

1. **`fetchWithTimeout(url, options, ms)` (new helper):** `Promise.race` between `fetch` and a timer (default 15s). Promise.race is used instead of `AbortController` so it works on every mobile browser; the timed-out request is simply ignored once the timeout rejects. No unhandled rejections (the race attaches handlers to both promises).
2. **`syncToServer()`:** now uses `fetchWithTimeout(..., 15000)` and **always leaves a clear result status** — success: "✅ সার্ভারে পাঠানো হয়েছে — Xটি বট চালু আছে।" (green); failure/timeout/non-ok: "❌ সার্ভারে পাঠানো যায়নি — নেটওয়ার্ক/সার্ভার সমস্যা, আবার চেষ্টা করুন।" (red, scrolls into view). This also fixes the standalone Sync button and the page-open auto-sync, which used to leave "sending..." on screen forever. (In the save flow, `verifySaved` may still overwrite the status with the verified result afterwards — that is the final word.)
3. **`verifySaved()`:** the GET `/api/bots` fetch now uses `fetchWithTimeout(..., 15000)`; a timeout lands in the 'unknown' branch, which still shows a clear result ("⚠️ সেভ হয়েছে, কিন্তু সার্ভার যাচাই করা যায়নি — নিচের Sync বোতাম চাপুন।"). Its three status branches now go through `finalStatus()` (see below).
4. **`parseCustom` / `parseBlocked`:** return `{ list, skipped }` instead of just a list. Skipped lines carry a Bengali reason: "স্পেস আছে", "ভুল ফরম্যাট", "৬৪ অক্ষরের বেশি", "একই কমান্ড দুইবার", "খালি লাইন", "২০টির বেশি (সর্বোচ্চ ২০টি)". The 20-cap extras are now reported too (previously silently sliced off). Slash + plain-text rules unchanged (v8.1).
5. **`pendingSkipped` + `finalStatus(msg, ok)` (new):** the Add-button handler stores the skipped lines before calling `saveBotList`. After the save finishes, `finalStatus` appends the warning — "⚠️ এই লাইনগুলো সেভ হয়নি: '/my command' (স্পেস আছে) — / দিয়ে শুরু হলে শুধু অক্ষর/সংখ্যা/_ চলবে, স্পেস চলবে না।" — and forces `ok=false` so `setStatus` scrolls it into view (unmissable). The save is **never blocked** — valid lines are saved, dropped lines are named. `pendingSkipped` is consumed once (cleared after showing, and on `saveFailed`).
6. **Table after save (fix 4 — verified, no code change needed):** `saveBotList` already does `bots = <WP-cleaned list>; renderList();` on success, and the PHP cleaner (`mla_bots_clean_one`) preserves custom/blocked commands. The "কাস্টম / বন্ধ কমান্ড" column shows the saved commands immediately; "—" means nothing was saved. The harness proves this. The "—" the user saw was because nothing was ever saved (both lists empty in `wp_options`) — which bugs 1–2 explain.
7. **Help lines:** the custom/blocked field help now says a wrong-format line won't save and will be named after saving. Field labels bumped (v8.2) → (v8.3).
