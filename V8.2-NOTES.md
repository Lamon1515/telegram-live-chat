# v8.2 — Notes (2026-11-08, morning)

## Problem it fixes

The user adds/blocks commands from wp-admin on his iPhone, but nothing ever
persisted — a read-only check proved both bots' custom/blocked fields were
completely empty in WordPress wp_options, even though desktop browser tests
of the same flow succeed. Three root causes:
1. The WordPress nonce (12h lifetime) expires if the admin tab stays open a
   long time; the save then fails silently with a 403/"-1".
2. The form was cleared BEFORE the save ran, so a failed save lost the input.
3. A Render restart/deploy wiped the server's in-memory bot list (including
   custom/blocked commands); only re-opening the admin page restored it.

## What changed per file

- **mla-bots-admin.php** (only file with logic changes; Version 1.1.1 → 1.1.2)
  - **Nonce auto-retry:** new AJAX action `mla_bots_fresh_nonce` (admin
    only, capability-gated; deliberately does NOT check the old nonce —
    that is the point). `saveBotList()` detects a nonce/403 failure
    (HTTP 403 or body "-1") and retries ONCE with a fresh nonce.
  - **No mutation until success:** the Add/Edit handler builds the list to
    send WITHOUT touching `bots` and WITHOUT clearing the form. Only a
    successful WordPress save commits `bots` (to the server-cleaned list)
    and clears the form. A failed save keeps every form value and the edit
    state, so a retry cannot create a duplicate. `removeBot` uses the same
    copy-then-commit pattern.
  - **Server verify:** after sync, `verifySaved(entry)` fetches
    GET /api/bots and compares the saved bot's custom/blocked command
    texts (sorted + lowercased; labels are display-only and ignored so a
    label truncation cannot cause a false mismatch). Success:
    "✅ সেভ হয়েছে — সার্ভারে যাচাই হয়েছে (কাস্টম Xটি, বন্ধ Yটি)".
    Mismatch/missing: "⚠️ ওয়ার্ডপ্রেসে সেভ হয়েছে কিন্তু সার্ভারে পাওয়া
    যায়নি — নিচের Sync বোতাম চাপুন". Unreachable: "⚠️ সেভ হয়েছে, কিন্তু
    সার্ভার যাচাই করা যায়নি — নিচের Sync বোতাম চাপুন".
    Deletions skip verify (the bot is supposed to be gone) and show the
    plain count success.
  - **Save button disabled while saving** (`setSaveBusy`), text becomes
    "⏳ সেভ হচ্ছে..."; it stays disabled until the whole flow (WordPress
    save + Render sync + verify) finishes, so a second click cannot start
    a duplicate save mid-flight; restored afterwards (edit-aware label).
  - **Errors unmissable:** `setStatus` scrolls the status area into view
    on errors; the duplicate-username error now points at the ✏️ button.
  - **Placeholders:** example VALUES removed from inside the fields.
    Custom placeholder is now "যেমন: ব্যালেন্স|/balance — প্রতি লাইনে
    একটি"; blocked is "যেমন: /withdraw, /admin". Help lines UNDER each
    field now state explicitly that the field starts EMPTY ("এই ঘরটি খালি
    থাকে — নিজে লিখতে হবে") and that plain text (no `/`) is allowed.
  - **Edit banner:** a yellow banner (`#mla-bot-edit-banner`) at the top
    of the form shows "✏️ @username সম্পাদনা করছেন — বদলে "সংরক্ষণ করুন"
    চাপুন।" while editing; hidden on cancel. Hint under the Add button:
    "আগে থেকে যুক্ত বট বদলাতে তার পাশের ✏️ সম্পাদনা চাপুন — নতুন করে যুক্ত
    করলে হবে না।"
  - **Hourly cron (wp-cron):** `mla_bots_sync_to_server()` (server-side
    wp_remote_post to /api/admin/bots/sync, same pattern as the accounts
    sync). `register_activation_hook` schedules `mla_bots_hourly_sync`
    (hourly); deactivation clears it; the callback syncs silently and
    records success in option `mla_bots_last_sync`. Defensive re-schedule
    on the admin page load in case the activation hook did not fire on a
    file-replace update. (wp-cron fires on site traffic; the EasyCron
    15-min wp-cron.php ping keeps it reliable.)
  - **Last sync line:** "শেষ সিঙ্ক: [Y-m-d H:i]" rendered server-side
    from `mla_bots_last_sync` ("এখনো হয়নি" if never). New AJAX action
    `mla_bots_mark_synced` (admin only) lets the browser record a manual
    sync success; `syncToServer()` calls it after a successful Render
    sync and the line updates live.
- **server.js** — UNCHANGED (no new endpoint was needed: verify uses the
  existing public GET /api/bots; the cron uses the existing POST
  /api/admin/bots/sync). The v8.1 click fix and plain-text command rules
  are untouched.
- **public/bot-page-snippet.html** — UNCHANGED (still v8.1; no page
  re-apply needed for this deploy).
- **public/widget.js** — UNCHANGED. **bots.json** — UNCHANGED.
- **README.md** — new v8.2 section (Bengali).

## Known limitations

- wp-cron only fires on site traffic; if the site gets no visits for hours
  the hourly sync slips (the EasyCron 15-min ping normally prevents this).
  The admin page auto-sync on open is the immediate fallback.
- The verify compares command texts only (labels ignored) — a label-only
  difference does not fail verification. That is deliberate.
- The accounts section's own AJAX saves (OTP verify, account sync) do NOT
  get the nonce retry in this version — only the bot-list save does.
